# 上手指南

从零把这条车跑起来：**装工具链 → 编译 → 烧录 → 连串口确认版本 → 三步自检 → 上车跑一圈**。
大约 30 分钟，其中一半时间在等编译。

> 已经熟的人可以直接跳到 [6. 起步跑一圈](#6-起步跑一圈)。

---

## 1. 你需要什么

| 项 | 说明 |
|---|---|
| 硬件 | 小车底板 V1.0、TB6612 模块、N20 带编码器电机 ×2、8 路灰度、OLED、HC-05 或 JDY-31 |
| 下载器 | ST-Link（推荐）或 DAP-Link，接 SWD：`SWDIO=PA13`、`SWCLK=PA14`、`GND`、`3V3` |
| 电源 | 2S（7.4 V）锂电 + XT60；**USB 供电时绝对不要接电机**（详见下） |
| 电脑 | Windows / macOS / Linux 均可，装 CMake + Ninja + `arm-none-eabi-gcc` |

> ⚠️ **USB 供电时禁止接电机**。底板上 Q1 的体二极管会把电池电压倒灌进 5 V 轨，
> 可能烧 USB 口或电脑主板。调逻辑先拔电机，测试电机时用电池供电。

## 2. 装工具链

需要三样：**CMake ≥ 3.22**、**Ninja**、**ARM GCC**（`arm-none-eabi-gcc`）。
关键是 `arm-none-eabi-gcc` 要在 `PATH` 里——工程只按前缀找编译器，不写死路径。

| 系统 | 推荐做法 |
|---|---|
| Windows / macOS / Linux 通用 | 装 [STM32CubeCLT](https://www.st.com/en/development-tools/stm32cubeclt.html)，然后把它的 `bin` 加进 `PATH` |
| Linux (Debian/Ubuntu) | `sudo apt install gcc-arm-none-eabi cmake ninja-build` |
| macOS (Homebrew) | `brew install --cask gcc-arm-embedded cmake ninja` |
| 用 CLion 的 | 直接用 CLion 自带的 toolchain，无需另装 |

CubeCLT 用户注意路径里带版本号，需要自己替换：

```bash
# Linux / macOS 示例
export PATH="$HOME/st/stm32cubeclt_1.21.0/bin:$PATH"
arm-none-eabi-gcc --version     # 能打印版本就 OK
```

## 3. 编译

```bash
git clone https://github.com/LUgABeEEE/DK-Line-following-car.git
cd DK-Line-following-car
git checkout simple            # 默认分支就是 simple；显式切一下更保险

cmake --preset Release         # 配置（只需一次）
cmake --build --preset Release # 编译
```

产物在 `build/Release/`：

| 文件 | 用途 |
|---|---|
| `linefllowing_car.elf` | 调试器直接烧 / 用来单步 |
| `linefllowing_car.hex` | STM32CubeProgrammer 烧（需先 `objcopy` 生成，见下） |
| `linefllowing_car.bin` | 同上，起始地址 `0x08000000` |

CMake 默认只产出 `.elf`，要 hex/bin 就手动转一次：

```bash
arm-none-eabi-objcopy -O ihex   build/Release/linefllowing_car.elf build/Release/fw.hex
arm-none-eabi-objcopy -O binary build/Release/linefllowing_car.elf build/Release/fw.bin
```

> **Debug 还是 Release？** 日常调试用 `Debug`（`-Og`，带调试信息）；
> 但 Flash 只有 64 KB，Debug 更胖，**接近上限时改用 Release**。
> 如果 `-O0` 下链接报 `region FLASH overflowed`，那是因为工程已经把 Debug 优化级别
> 从 `-O0` 提到 `-Og` 了，别改回 `-O0`。

不想装工具链？去 [Actions](https://github.com/LUgABeEEE/DK-Line-following-car/actions/workflows/build.yml)
随便点一次构建，页面底部 **Artifacts** 里有现成的 `firmware-Release`（含 hex/bin/elf）。
正式版本直接下 [Release](https://github.com/LUgABeEEE/DK-Line-following-car/releases) 里的附件。

## 4. 烧录

### STM32CubeProgrammer（图形界面）

1. 接线：ST-Link 的 `SWDIO / SWCLK / GND / 3V3` 接底板对应脚（板上有 SWD 排针）
2. 打开 CubeProgrammer → 左上选 **ST-LINK** → 点 **Connect**
3. 右侧 **Erasing & Programming** → 选 `.hex` 或 `.bin`（选 bin 时地址填 `0x08000000`）
4. 勾选 *Verify programming* → **Start Programming**

### ST-Link Utility / OpenOCD / pyOCD

`.elf` 一般可以直接烧；`.hex` 通用；`.bin` 必须指定基址 `0x08000000`。

烧完按一下复位键（NRST），板子开始跑。

## 5. 连串口，确认版本

这一步能省掉后面 80% 的"我以为是代码问题其实没烧进去"。

**接线**：USART2 → `PA2 = TX`、`PA3 = RX`，波特率 **9600 8N1**。
可以走蓝牙模块（HC-05 / JDY-31 配对码通常 `1234`），也可以直接 USB-TTL 接 PA2/PA3。

连上后应该看到类似这样的输出：

```
[VER] line-follower dn P1 (built Oct 30 2026 14:49:43)
[M] heap… stkC… mod=HC-05 cfg… baud=9600
[L] LINE e0.1 s0.0 L50.0 R50.0 sd+0 sc=LINE …
```

怎么读：

| 行 | 含义 |
|---|---|
| `[VER]` | **构建标记**（这里是 `dn`）+ **档位**（`P1`）。烧错版本、切错档位，一眼就能看出来 |
| `[M]` | 诊断：剩余堆、各任务栈水位、I2C 错误数、识别到的蓝牙模块型号与波特率 |
| `[L]` | 运行态主行，约 5 Hz：误差 `e`、差速 `s`、左右轮目标 `L/R`、场景 `sc`、角点方向 `cd`、yaw 等 |
| `[I]` | 陀螺仪：`WHO_AM_I`、yaw 符号、yaw 角度、角速度、零偏、故障计数 |
| `[T]` | 跑圈打标：`[T] OK #3` / `[T] FAIL #4`（下面第 7 节讲怎么打） |
| `[RACE]` | 自动停车事件：`det`（识别到启停线）与 `stop`（停车） |

**如果什么输出都没有**：先确认波特率是 9600（不是 115200），再确认 TX/RX 有没有接反。

## 6. 起步跑一圈

### 6.1 三步自检（第一次上车必做）

打开 `Core/Src/main.c`，在 `USER CODE BEGIN 2` 那一段有一排被注释掉的自检调用。
**每次只取消注释一行**，编译、烧录、跑完看结果，再注释回去换下一条：

```c
// Motor_TestSequence();      /* 1. 电机：正转/滑行/反转/刹车，约 10 秒，轮子要架空 */
// Encoder_TestSequence();    /* 2. 编码器：手拨轮子看计数，约 6 秒 */
// Speed_PID_TestSequence();  /* 3. 速度环：阶跃响应，约 5 秒，轮子要架空 */
// Gray_TestSequence(&g_gray, &hi2c1);  /* 4. 灰度：8 路模拟值/阈值/位置 */
// LinePD_VerifySigns(&g_line_pd, &g_gray, &hi2c1, 0);  /* 5. 符号：线放左/中/右，看 error 正负 */
```

判据：

| 自检 | 正常的表现 |
|---|---|
| 电机 | 先正转缓升、滑行、反转、刹车；两个轮子都要动 |
| 编码器 | 手往前拨轮子，计数**增加**；往后拨，计数**减少**。手转一整圈约 **1300** 个计数 |
| 速度环 | 串口三列「目标 / 实测 / 输出」，实测能跟到目标附近，不持续打满 |
| 灰度 | 8 路数值随手遮挡变化；线在正中间时位置误差 ≈ 0 |
| 符号 | 线放**左**边 `e` 为正、放**右**边为负 |

有两处必须提前确认，否则后面全是玄学：

- **编码器方向**：手推车前进时 `[L]` 里的速度得是**正**的。反了改 `Drivers/BSD/Src/Encoder.c` 里的 `ENCODER_A_DIR_SIGN / ENCODER_B_DIR_SIGN`。
- **电机方向**：自检时车要是往后走，改 `Drivers/BSD/Src/PWM.c` 里的 `MOTOR_A_DIR_SIGN / MOTOR_B_DIR_SIGN`。

> 没装 MPU6050 也能跑（`MPU6050_IsReady()` 为假时自动跳过 yaw 相关逻辑），
> 只是少了陀螺阻尼和定角转弯，过直角会更靠搜索。

### 6.2 按键怎么用

三个键，短按 / 长按是不同功能：

| 操作 | 作用 |
|---|---|
| **KEY3 短按** | 切换调参页（KP → KI → KD → KFF → TARGET → ENCA → SENSOR → MODE → LKP → LKD → LBAS → LAP → ALAT → MARG → 循环） |
| **KEY1 / KEY2 短按** | 当前参数 −1 步 / +1 步 |
| **KEY2 短按**（在 MODE 页、且处于 STOP） | **直接进 LINE（循迹）** |
| **KEY1 长按**（在 MODE 页、且处于 STOP） | 进 SPD（速度测试，车会直着走，轮子要架空） |
| **KEY2 长按** | **急停**（切停车 + 清积分 + 硬制动），任何时候都有效 |
| **KEY1 短按**（循迹中） | 本次跑 **失败** → 串口打 `[T] FAIL` |
| **KEY3 长按** | 本次跑 **成功** → 串口打 `[T] OK`，并把页面退回 MODE 页 |

> 循迹运行中 OLED **刻意冻结刷新**：屏幕和 MPU6050 共用 I2C2，刷新会和陀螺仪抢总线，
> 拖慢控制任务。跑车时想看实时数据请用串口的 `[L]` 行，不要看屏幕。

### 6.3 一圈自动停车

`LAP` 参数决定自动停车怎么工作：

| LAP | 行为 |
|---|---|
| `0` | 关闭自动停车，只能长按 KEY2 停 |
| `10 ~ 40` | **自适应**：不填周长，纯靠启停线识别（从 0 按一下 KEY2 就是 10，正好进这档） |
| `≥ 50` | **周长模式**：填一圈周长（cm），识别为主、里程兜底 |

`MARG` 是刹车余量：识别到启停线后，再走 `17 − MARG` 厘米停住。
**车停早了就减小 MARG，冲过线就加大 MARG**（步长 0.5 cm），改完跑三次取平均。

跑之前建议：先 `LAP=10`（自适应）跑一圈，确认能停；再决定要不要切周长模式。

## 7. 打标与复盘

跑完一圈，用按键给结果打标（`[T] OK` / `[T] FAIL`），配合 `tools/` 下的脚本可以把
「哪几次成功、用时多少、丢线几次」自动统计出来：

```bash
# 1. 采一段蓝牙串口日志（PIN 默认 1234，先 bluetoothctl pair/trust 一次）
python3 tools/bt_serial_capture.py --mac AA:BB:CC:DD:EE:FF --duration 120

# 2. 按打标切分，统计每圈用时与异常
python3 tools/tag_report.py logs/serial_*.log
```

更多脚本（解析、汇总、协议自测）见 [`tools/README.md`](../tools/README.md)。

## 8. 调参顺序（别乱来）

**先内环，后外环**。内环没稳就调外环，等于在晃的地基上盖楼。

| 顺序 | 参数 | 怎么调 |
|---|---|---|
| 1 | `KFF` | Kp=Ki=Kd=0，只留前馈，让实测速度接近目标；偏小就按 `目标/实测` 放大 |
| 2 | `KP` / `KI`（内环） | 加 P 让响应快、超调 < 20 %；加 I 消静差；`KD` 内环一般保持 0 |
| 3 | `LBAS` | 循迹基础速度。**受电机上限约束**——实测约 57 cm/s 就打满占空比，超过就是长时间饱和 |
| 4 | `LKP` / `LKD` | 外环。先 P 跟线不画龙，再加 D 压过冲。注意 D 项被 `1/dt` 放大 25 倍，很敏感 |
| 5 | `ALAT` | 曲率限速（允许的最大侧向加速度）。调大 = 弧线更快，可能甩出去 |
| 6 | `LAP` / `MARG` | 自动停车的周长与刹车余量 |

全部参数都能在**运行中用按键改**，不用重新编译——调好了再写回头文件里的默认值，
不然下次上电就丢了。

> 参数默认值在 `Drivers/BSD/Inc/LinePD.h`（外环）和 `SpeedPID.h`（内环），
> 文件头注释里写了每个值的实测依据，改之前建议读一遍。

## 9. 常见问题

| 现象 | 先查什么 |
|---|---|
| 串口全是乱码 | 波特率不对。USART2 是 **9600**，不是 115200 |
| 屏幕不亮 | I2C2 上有没有别的设备抢地址；`[M]` 行的 `i2c` 错误计数是否在涨 |
| 上电电机就转 | 先确认 `CTRL_TASK_ENABLE_MOTION`，再看 `MODE` 页是不是停在 LINE/SPD |
| 车往一边偏 | 两轮「同读数不同速」：用 `ENCA` 分轮修正（每次 0.005 量级） |
| 高速时抖 / 画龙 | 外环周期与 Kp 不匹配，先降 `LKP`；也可能是 `LKD` 太大把量化噪声放大了 |
| 一直不自动停 | `LAP` 是否为 0；`[L]` 里的 `sn/bn` 计数器有没有涨（涨了说明压到线但判据被拒） |
| 车完全不动 | `[VER]` 确认固件跑起来了；长按 KEY1 能否进 SPD；`[L]` 里 `L/R` 目标是否为 0 |
| 蓝牙连上没数据 | `[M]` 行的 `baud` 与实际是否一致；模块是 HC-05 还是 JDY-31 会被自动识别 |
